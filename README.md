# ZONA

Собственный игровой движок (Rust), игра и лаунчер. Сеттинг — Зона в духе братьев
Стругацких («Пикник на обочине»): аномалии, артефакты, экспедиции, исследования.

## Что это

- **Движок с нуля**: `winit` + `wgpu` (Vulkan/DX12) + `rapier3d` + собственный ECS-слой
  на `hecs` с фиксированным тиком симуляции.
- **Игра**: 3D FPS, extraction-рейды (заход со своим снаряжением, добыча выносится,
  смерть = потеря лута), между рейдами — база. PvP + PvE, лут, выживание, прокачка,
  квесты, отрядные сессии 5–10 игроков.
- **Лаунчер**: свой Rust-лаунчер (GUI + CLI), обновления по `manifest.json`
  с GitHub Releases (zip-архивы + SHA-256), выбор папки установки игроком.

## Сборка и запуск (Windows)

```powershell
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p zn-client                            # offline: demo_zone
cargo run -p zn-client -- --level kordon          # offline: одиночная сцена
cargo run -p zn-client -- --server 127.0.0.1:7700 # мир локаций (M4d)
cargo run -p zn-server -- --port 7700 --max-players 10   # мир локаций
cargo run -p zn-server -- --level demo_zone               # одиночная сцена
cargo run -p zn-server -- --sim-latency-ms 120 --sim-loss-pct 10
cargo run -p zn-launcher                            # dev-режим: клиент из рабочего дерева (GUI)
cargo run -p zn-launcher -- --cli                   # то же, но консольным режимом
cargo run -p zn-tools-editor --bin zn-editor
```

Платформа релиза: Windows x64 (wgpu выбирает Vulkan/DX12 автоматически).

## Тулчейн

- Минимальная версия Rust — **1.95** (`rust-version` workspace).
- Целевой тулчейн для разработки: `stable-x86_64-pc-windows-msvc`
  (`rustup default stable-x86_64-pc-windows-msvc`), как в CI. Запуск клиента —

  ```powershell
  cargo run -p zn-client
  ```

  Требуется MSVC-линкер из **Visual Studio Build Tools** (workload
  «Разработка классических приложений на C++» + Windows SDK):

  ```powershell
  winget install --id Microsoft.VisualStudio.2022.BuildTools `
    --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.Windows11SDK.22621 --includeRecommended"
  ```
- Альтернатива — `stable-x86_64-pc-windows-gnu` (rustup):
  `.cargo/config.toml` проекта принудительно переназначает gnu-линкер на
  bundled-gcc тулчейна rustup (`lib/rustlib/x86_64-pc-windows-gnu/bin/self-contained/...`),
  потому что системный WinLibs (Brecht Sanders) gcc, прописанный глобально в
  `~/.cargo/config.toml` этой машины, линкует бинарники с битой таблицей импортов.
  Ранее из-за этого `zn-client` падал на старте с `0xC0000005` в
  `std::sys::pal::windows::init`; ныне разработка идёт на MSVC, где проблемы нет.
- CI (`.github/workflows/ci.yml`) использует стандартный MSVC-тулчейн GitHub-runner.

## Контент

Уровни — RON-файлы `game/content/levels/<имя>.scene.ron`, ассеты —
`game/content/assets/` (glTF/GLB, PNG/JPEG, KTX2: uncompressed и Basis Universal).
Клиент читает
корень контента из `--content-root` (или `ZN_CONTENT_ROOT`, по умолчанию
`game/content`) и уровень из `--level <имя>`; если файл не найден — предупреждение
и fallback на `demo_zone()`. Редактор: `cargo run -p zn-tools-editor --bin zn-editor` —
New/Open/Save `.scene.ron`, орбитальная камера, пикинг объектов, gizmo
(перемещение/вращение), браузер ассетов с размещением (клик пересекает луч с
землёй y=0 или ближайшим боксом коллайдера), панель свойств (position, scale,
yaw, tint, asset, material, collider, solid + «Материал поверхности»: текстура,
uv scale, мировые UV, roughness/metallic/emissive), undo/redo правок
(Ctrl+Z/Ctrl+Y и кнопки в меню — снимки «до/после» со склейкой серий драгов в
одну команду, глубина 200). Одноразовая выгрузка демо-уровня:

```powershell
cargo run -p zn-tools-editor --bin zn-editor -- --emit-demo game/content/levels/demo_zone.scene.ron
```

Выгрузка всего мира M4d (реестр + сцены локаций, M4d-1):

```powershell
cargo run -p zn-tools-editor --bin zn-editor -- --emit-world game/content
```

Мир локаций: реестр `game/content/locations.ron` (`id`, `name`, `scene`, `base` —
признак безопасной базы) и сцены `game/content/levels/{base,kordon,svalka,podzemka}.scene.ron`.
Мир встроен и в код (`zn-scene`: `LocationRegistry::builtin`/`Scene::builtin_world`) —
сервер и клиент падают на него, если файлы не прочитаны (хэши обязаны сойтись).
Схема объекта: `position`, `scale`, `yaw`, `color`, `asset` (`builtin://cube/sphere/
cylinder/quad` или относительный путь к glTF), `material` (имя материала внутри
ассета), `collider` (`box`/`cylinder`/`sphere`, по умолчанию box у solid-объектов),
`solid`, `loot` (ящик: список `[(item, count), …]`), а также материал поверхности
(M4g): `texture` (`builtin://concrete|asphalt|metal|dirt|checker|noise`), `uv_scale`
(тайлинг), `world_uv` (мировые box-UV), `roughness`/`metallic`/`emissive`
(переопределения; по умолчанию — диэлектрик 0.85). Сцена дополнительно несёт
`spawn`/`spawn_yaw`, `anomalies`, `transitions` (пешие переходы: `position`,
`radius`, `target`, `target_position`, `target_yaw`, `label`), `bubbles`
(кандидаты пузырей: якорь + радиус) и `bubble_arrivals` (точки прибытия
телепорта), `extractions` (круги экстракции M4d-2: якорь, `radius`, `percent`
сейва, `label`). Неизвестные поля получают
значения по умолчанию (back-compat с RON M1).
Каталог предметов — `game/content/items/items.ron` (`key`, `display_name`,
`weight_kg`, `stack_max`, `use_effect` с лечением, `carry_effect` с эффектами
ношения: `heat_resist`/`weight_cut` — M4d-3a); сетевой номер предмета —
индекс в каталоге, отсортированном по `key`, и хэш каталога едет в handshake.
Asset-ключи — строки, межкратные ID (`MeshId`/`MaterialId`) живут только внутри
`zn-render`. Загрузка ассетов в клиенте — фоновый поток (std::thread + mpsc);
не загруженное показывается builtin-кубом. GPU-кэши с LRU-выселением по бюджетам
256 МиБ (меши) / 512 МиБ (текстуры). Текстуры грузятся с CPU box-мип-цепочкой
(сэмплер LinearMipLinear). Материалы с `AlphaMode::Blend` рисуются вторым
проходом back-to-front после непрозрачных.

KTX2: uncompressed и Basis Universal (ETC1S/BasisLZ и UASTC, в т.ч. с
Zstd-суперкомпрессией) — транскод в RGBA8 на CPU через `basisu`; BCn-compressed
форматы вне объёма (фолбэк на PNG/JPEG/uncompressed KTX2). Прокси-коллайдеры
статики строятся при (пере)загрузке уровня; смена масштаба объекта в рантайме
их не пересчитывает.

## Сеть (M3–M4d)

Dedicated-сервер и клиент общаются по UDP (bincode, протокол v8; одна датаграмма —
одно сообщение; бюджет 1400 Б, фрагментация не реализована). Один процесс
сервера — один матч, до 10 игроков. С M4d сервер без `--level` ведёт мир
локаций (одна симуляция на локацию), с `--level <имя>` — одиночную сцену.

- **Клиент**: `--server host:port`. Handshake `ClientHello` (версия протокола +
  `content_hash` уровня + `items_hash` каталога + имя) с повтором каждые 500 мс;
  `ServerReject` (версия/контент/нет слотов) → offline. Дальше — `InputPacket`
  (последние 4 инпута: потеря датаграммы не превращается в потерю движения),
  `Ping` раз в секунду (RTT — в заголовке окна), `ClientBye` при выходе.
- **Симуляция** 60 Гц — общая кинематика `zn-sim` у клиента и сервера; снапшоты
  30 Гц с персональным `acked_input_tick`. Клиент предсказывает движение локально
  и сверяет со снапшотом: reconcile = восстановление состояния → реплей
  неучтённых инпутов → сравнение; небольшие поправки гаснут визуально (~0.15 с),
  большие (> 2 м) — мгновенный снап.
- **Удалённые игроки** рисуются капсулами с интерполяцией (рендер на 100 мс
  назад, пара снапшотов вокруг тика, yaw по кратчайшей дуге); цвет детерминирован
  по `player_id`. Себя клиент не рисует.
- **Таймауты**: сервер забывает клиента после 5 с тишины; клиент уходит в offline
  после 3 с без снапшотов (заголовок окна: «нет связи»). Реконнекта нет — перезапуск.
- **Ограничения M3**: нет фрагментации (≤ 1400 Б), игроки не сталкиваются друг с
  другом, сервер авторитетен (античит вне рамок); бой — в M4a, лут и инвентарь —
  в M4b, аномалии и болты — в M4c ниже.
- **Консоль сервера**: `status`, `list` (с локацией клиентов), `kick <id>`,
  `spawn` (отладочный игрок), `loot <id> <item> <count>`, `tp <id> <location>`,
  `bubbles [<location>]`, `quit`. Флаги `--sim-latency-ms`/`--sim-loss-pct`
  имитируют задержку и потери исходящих (для ручной проверки, не для CI).
- **Smoke**: `cargo run -p zn-server` + два `cargo run -p zn-client -- --server
  127.0.0.1:7700`; выход одного клиента убирает его капсулу у второго, kick с
  консоли — то же самое.

## Бой (M4a)

PvP-бой: серверный hitscan-винтовкой (авто-огонь), урон зонами по высоте попадания,
смерть с респавном, HUD и события выстрелов для всех клиентов.

- **Стрельба**: ЛКМ (при захваченном курсоре) удерживается — выстрел каждые
  8 тиков (~7.5/с), дальность 100 м. Луч выходит из глаз (1.62 м), стены уровня
  блокируют выстрел, хитбокс игрока — капсула; отдача и разброс не реализованы.
- **Урон**: 100 HP; торс — 25, голова ×2 (50), ноги ×0.6 (15). Зоны по высоте от
  ступней: голова ≥ 1.5 м, торс 0.8–1.5 м, ноги < 0.8 м.
- **Смерть/респавн**: 0 HP — смерть: мёртвый не двигается и не стреляет, но может
  осматриваться, у других не рисуется — вместо капсулы остаётся труп-контейнер
  (M4b); через 180 тиков (3 с) — респавн на точке спавна уровня с полным
  здоровьем. Friendly fire всегда включён.
- **Протокол**: `health` в состоянии игрока, `GameEvent` (`Shot` — трейсер и
  вспышка у всех, `Death` — с именами от сессии); события копятся между
  снапшотами и едут в них (30 Гц), размер датаграммы проверен тестом
  (10 игроков + события; с M4c бюджет — 1400 Б под болты и аномалии).
- **HUD** (egui, пассивный — ввод не перехватывает): прицел, HP-полоска и число,
  kill-фид (3 последние смерти, 4 с, «Вы» для себя), экран смерти с именем убийцы
  и отсчётом до возрождения.
- **Ограничения M4a**: без лаг-компенсации (хитрег по позиции на момент обработки
  тика), без отдачи/разброса/звука, без PvE, одно оружие (винтовка), урона от
  падения нет, анимаций смерти нет (труп — лежачий бокс, M4b).
- **Smoke боя**: сервер + 2 клиента; стрельба ЛКМ, HUD и килл-фид, смерть — экран
  «ВЫ УБИТЫ» и респавн через ~3 с.

## Лут и инвентарь (M4b)

Обыск контейнеров, инвентарь с весом, выброс/подбор предметов и лечение аптечкой
или бинтом. Игра не встаёт на паузу: панели passive, курсор остаётся в игре.

- **Каталог предметов**: `game/content/items/items.ron` — 8 предметов (патроны,
  бинт, болт, консервы, аптечка, водка; артефакты «Жар-камень» и «Тягун»
  добавлены в M4c): вес, максимум стопки, эффект. Сетевой номер предмета —
  индекс в каталоге, отсортированном по `key`; хэш каталога едет в handshake
  (несовпадение — отказ как при другом уровне).
- **Ящики**: объекты сцены с полем `loot` (`[(item, count), …]`, позиция — центр
  крышки); обыск — E: цель в радиусе 2 м (XZ) и в конусе взгляда, выбор — по
  прицелу, как у боя. Панель обыска персональная: чужой лут не виден, содержимое
  общее и убывает для всех.
- **Инвентарь**: сетка 8×5, лимит 50 кг; автоукладка — сначала в существующий
  стак, затем в первую свободную ячейку. Взять: Enter (выделенную строку) или
  T (всё, что влезает по весу); выбросить: Q (выделенный стак улетает перед
  игроком); использовать: Enter на ячейке инвентаря.
- **Лечение**: аптечка +50 HP за 2 с, бинт +25 HP за 1 с; расход — в конце,
  смерть отменяет без расхода. Не начинается при полном HP и во время активного
  лечения. Прогресс — зелёная полоска над HP.
- **Трупы**: смерть оставляет на месте игрока лежачий бокс-контейнер с его лутом
  (убийца забирает добычу); труп гаснет через 5 минут. Обыск — как у ящиков;
  панель закрывается при отходе (> 3 м), смерти или исчезновении трупа.
- **Протокол v4** (в M4c обновлён до v5, в M4d — до v6): `ClientHello` + `items_hash`; `Interact`/`InventoryAction`
  (монотонный `tick` — действия уходят с 4-кратным повтором, сервер
  дедуплицирует), персональные `InventoryUpdate`/`ContainerUpdate` (контейнер
  `0` — закрыт), `loot`/`corpses` в снапшотах (позиции — квант 0.1 м, yaw —
  1/256 оборота).
- **HUD**: панели обыска и инвентаря (справа снизу, фокус — ярче рамкой),
  название и вес выбранного, «Вес: X / 50 кг», строка подсказки «[E]
  Обыскать/Подобрать» под прицелом.
- **Ограничения M4b**: нет торговли и передачи предметов между игроками (только
  трупы/земля), drag&drop нет (автораскладка), на земле ≤ 32 предмета (старейшие
  вытесняются), лут трупа чужому не виден (только сам труп). Расход патронов,
  еда и эффекты артефактов — M4d-3a; звук — A1.
- **Smoke лута**: сервер + 2 клиента; ящик у спавна — E, T — взять всё, I —
  инвентарь (вес/выбор), Q — выброс виден второму игроку, аптечка — полоска
  лечения, смерть — труп с лутом.

## Экстракция и персист стэшей (M4d-2)

- **Круги экстракции**: `extractions` в сцене (якорь, радиус, `percent` сейва,
  подпись). По одному кругу на рейдовую локацию — в дальнем углу карты; на базе
  кругов нет. Вход живого игрока в круг: InventoryAll делится по весу на
  сохраняемую часть (`percent`, граничная стопка режется по единицам веса) и
  остаток; сохранённое уходит в персональный склад, остаток падает предметами в
  круге (его может подбрать любой). Игрок появляется на базе.
- **Выбор маршрута**: ворота базы — бесплатный выход со 100 % добычи (идти
  пешком); круг — быстрый выход, но с потерей доли (`percent` = 0.75 в контенте).
  Смерть — потеря всего вне базового инвентаря (труп с лутом, M4b).
- **Протокол v7**: `ClientHello.profile: Option<String>` — ключ персонального
  склада; `GameEvent::Extracted { player, player_name, percent }` — событие в
  снапшоте локации (экстрактор видит панель результата, остальные — строку в
  килл-фиде; звук — чойс из A1).
- **Профиль и стэш**: клиент шлёт профиль из `ZN_PROFILE` (не задан — склад живёт
  только в памяти сессии, как в M4d). Сервер пишет `stashes.ron`
  (`--stash-file <путь>`, по умолчанию `stashes.ron` в рабочей директории;
  `--no-stash` — выключить) версионированно и атомарно (tmp + rename), при
  отключении профиля и по `quit`; битый/чужой файл — предупреждение и пустой
  склад (fail-soft). Реконнект с тем же профилем возвращает склад.
- **Smoke**: сервер + 2 клиента; лут → круг на Кордоне (гасит/маяк, зелёное
  кольцо) → панель «ЭВАКУАЦИЯ» у экстрактора и строка у второго → стопки в
  складе (H), остаток лежит в круге; рестарт сервера с тем же `ZN_PROFILE` —
  склад на месте.

## Выживание данными (M4d-3a)

- **Патроны**: выстрел расходует `ammo_545` из инвентаря (сервер авторитетен);
  без патронов — «сухой» курок (никакого выстрела, локальный отклик клиента
  тоже молчит). Каталог без `ammo_545` — стрельба не ограничена (кастомный
  контент). Счётчик «Патроны: N» — под HP, пустой магазин красный.
- **Еда**: `canned_food` лечит 10 HP за 4 с (тот же механизм `UseStarted`, что
  аптечка/бинт). Консервы и водка остались в луте — теперь не только груз.
- **Эффекты ношения**: `carry_effect` в каталоге (`heat_resist` — множитель
  урона жгучих аномалий, `weight_cut` — прибавка к лимиту веса). Действует,
  пока предмет в инвентаре; сильнейший эффект каждого типа суммируется без
  стаков (берётся максимум). В контенте: Жар-камень −50 % урона жгучих, Тягун
  +20 % к весу. Сильнейший эффект — строка под патронами.
- **HUD/подсказки**: патроны и эффект артефакта (offline — из симуляции, сеть —
  из персональных апдатов инвентаря).
- **Ограничения**: эффекты читаются из инвентаря без вычета (могут меняться
  при пересадке); радиация не реализована (выбросы — M4d-3b); звуки еды —
  общий набор A1.

## Нокдаун и выбросы (M4d-3b)

- **Нокдаун**: первый смертельный удар с здоровья выше `KNOCKDOWN_HP` (25) не
  убивает — игрок падает (1 HP, 12 с): не двигается, не стреляет, любой
  следующий урон добивает. По таймеру встаёт с 25 HP. Удар с «низкого»
  здоровья (≤ 25) сразу убивает; добивание в нокдауне — смерть с трупом.
  События `KnockedDown`/`GotUp` едут в снапшоте; клиент показывает оверлей с
  таймером (offline — из локальной симуляции).
- **Выброс**: серверный цикл 180 с ожидание → 30 с предупреждение → 15 с
  активная фаза. В предупреждении клиент видит «ВЫБРОС ЧЕРЕЗ N с», в активной
  — красную пелену и урон: 8 HP/с всем живым игрокам вне базы (база — безопасная
  зона). Урон идёт через нокдаун/смерть штатными путями, так что в поле можно
  лечь и не успеть встать. Состояние выброса приходит в каждом снапшоте
  (`Blowout { active, seconds_left }`) — клиент не считает сам. Тайминги — в
  `SessionConfig::blowout` (`BlowoutTiming`), в тестах укорачиваются.
- **Протокол v8**: `GameEvent::{KnockedDown, GotUp, Blowout}`; имена в
  событиях нокдауна заполняет сервер (как у `Death`).
- **Smoke**: сервер + 2 клиента; один — на базе, второй — на Кордоне; дождаться
  предупреждения (3 мин), уйти на базу или поймать выброс в поле (нокдаун,
  затем подъём или смерть), проверить HUD-оверлеи.

## Аномалии и артефакты (M4c)

Две аномалии в demo_zone, болты как «щуп» и артефакты, лежащие в аномалиях с
начала рейда. Аномалии не входят в столкновения: эффекты считает симуляция,
визуал — клиент.

- **Аномалии**: жгучая — урон внутри сферы (радиус 3 м): каждые 15 тиков 2–6 HP
  по близости к центру; гравитационная — тянет к оси (радиус 3.5 м): у центра
  5 м/с — сильнее пешего шага (5.5), но спринт (8.5) выносит, урона нет. Центр
  сферы — якорь + радиус вверх, «сердце» цели — ступни + 0.9 м. Смерть в
  аномалии — обычный труп с лутом, в килл-фиде подписана «Аномалия» (убийцы нет).
- **Болт**: G — бросок (1 болт из инвентаря, кулдаун 20 тиков, в полёте ≤ 12
  болтов на мир, живёт до 10 с). Летит по дуге (та же гравитация, скорость
  18 м/с), останавливается статикой и падает предметом — подбирается E. Игрокам
  урона не наносит. Болт, влетевший в аномалию, гибнет со вспышкой: аномалия
  ярко проявляется на 5 с — видят все (событие в снапшоте).
- **Артефакты**: «Жар-камень» в жгучей и «Тягун» в гравитационной аномалии
  demo_zone; лежат в якоре с начала матча, подбор — как обычный предмет на земле.
  Эффектов и ценности у них нет (заготовка под M4d).
- **Протокол v5**: `ThrowBolt` (дедупликация по tick), `bolts` в снапшотах
  (id, владелец, квантованная позиция), `AnomalyRevealed` (индекс аномалии и
  точка срабатывания болта — для вспышки). Снапшот самого полного случая
  (10 игроков + 32 предмета + 4 трупа + 12 болтов + события) ≤ 1400 Б — без
  фрагментации UDP на Ethernet.
- **Визуал**: аномалии — еле заметные мерцающие сферы (альфа ~0.12), по цвету
  типа (жар — оранжевый, тяга — фиолетовый); проявленные — ярче, плюс вспышка в
  точке срабатывания. Болты интерполируются между снапшотами.
- **Ограничения M4c**: без телепорт-эффектов, радиации/дозиметра, выбросов,
  порчи лута в аномалиях и звука; аномалии влияют только на игроков и болты.
- **Smoke аномалий**: сервер + 2 клиента; прогулка в жгучую — HP падает, смерть
  с подписью «Аномалия» и трупом; бросок G в гравитационную — вспышка и
  подсветка; артефакт — E у якоря аномалии.

## Мир локаций и база (M4d-1)

Четыре локации, связанные пешими переходами и пузырями-телепортами; на базе —
спавн и персональный склад, куда автоматически уходит вся добыча.

- **Локации**: База (id 0), Кордон (1 — переработанный demo_zone с ящиками,
  аномалиями и артефактами), Свалка (2), Подземка (3). Каждая локация — своя
  симуляция на сервере; игрок живёт в одной из них, снапшоты и удалённые игроки
  видны только внутри своей локации. Расстояние до базы — 0/1/2/2.
- **Хэш мира**: handshake покрывает реестр и все сцены (`world_content_hash`);
  клиент без `--level` в сети грузит `locations.ron` и сцены сам, расхождение —
  отказ, как при другом уровне. В одиночном режиме (`--level`) хэш — только
  сцены, переходы и пузыри выключены.
- **Переходы пешком**: круг `radius` на полу вокруг `position` — вход переключает
  в `target` (точка `target_position` с поворотом `target_yaw`) без таймера;
  гистерезис не даёт дребезжать у границы. У ворот базы точки прибытия отнесены
  так, чтобы обратный переход не срабатывал сразу.
- **Пузыри**: в сцене — кандидаты (`bubbles`) и точки прибытия (`bubble_arrivals`);
  сервер держит 2–3 активных на карту. Вход — телепорт (проверяется «сердце»
  игрока: ступни + 0.9 м): локация строго ближе к базе (со Свалки/Подземки — на
  Кордон, с Кордона — на Базу); ближе некуда — игрок прибывает в точку
  `bubble_arrivals` своей же сцены. Использованный пузырь исчезает и через 90 с
  рождается в случайном свободном кандидате. Активные якоря едут в снапшотах
  локации — клиент рисует полупрозрачные сферы (радиус — от кандидата сцены).
- **База и склад**: вход на базу (пешком или пузырём) автоматически сдаёт весь
  инвентарь в персональный склад (100 %). Склад хранится до отключения игрока;
  с профилем (`ZN_PROFILE`) — переживает сессии через `stashes.ron` (M4d-2).
  Операции — только на базе,
  панель H: Enter на складе берёт стопку, при фокусе на инвентаре Enter сдаёт
  ячейку; стопки не сливаются. Сервер шлёт свежий `StashUpdate` при входе на
  базу и после Welcome.
- **Протокол v6** (в M4d-2 — v7): `ServerWelcome.location`; `StashAction`
  (`Put { slot }` / `Take { index }`, дедупликация по tick, повтор как у прочих
  действий) и персональный `StashUpdate`; `LocationChanged { location, position,
  yaw }` — клиент пересоздаёт сцену, коллайдеры и локальную симуляцию, переносит
  игрока в точку прибытия и кратко вспыхивает белым экраном; `bubbles` в
  снапшотах.
- **HUD/титул**: заголовок окна — `ZONA — База · ping N ms` (локация + статус
  связи); панель склада рисуется слева от обыска/инвентаря, строки контейнера и
  склада совпадают индексами с серверными (неизвестный каталогу предмет —
  строкой-заглушкой, взять его всё равно можно).
- **Ограничения M4d-1**: новые локации — песочницы без PvE-врагов и своего лута
  (кроме Кордона); сигнал (аварийный ТП почти к базе) и радиация — не
  реализованы; выбросы — M4d-3b; клан/общий склад отсутствует.
- **Smoke мира**: `cargo run -p zn-server` + два `cargo run -p zn-client --
  --server 127.0.0.1:7700`; пройти в ворота (титул меняет локацию, вспышка),
  вернуться на базу с лутом — инвентарь уходит в склад (H, Enter — взять
  обратно; фокус инвентаря + Enter — сдать ячейку); `tp <id> 2` + `bubbles 2`
  на консоли сервера — пузырь на Свалке уносит на Кордон.

## Графика (M4g)

- **Атмосфера (G1a)**: `SceneEnvironment` в сцене (солнце: направление/цвет/
  интенсивность, ambient, туман: цвет/плотность, небо: зенит/горизонт) — свой вид
  у каждой локации; процедурное градиентное небо с диском солнца и экспоненциальный
  туман в линейном пространстве до ACES. Клиент и редактор применяют параметры
  сцены каждый кадр (`set_atmosphere`).
- **Тени (G1b)**: одна ортографическая карта теней на локацию (2048², Depth32Float)
  по AABB сцены, PCF 3×3, фронт-каллинг + slope-scale bias; затеняется только
  прямой свет солнца.
- **Материалы и текстуры (G2)**: встроенные процедурные текстуры в `zn-assets`
  (бетон, асфальт, металл с ржавчиной, земля, шахматка, шум): 256², бесшовные,
  детерминированные, с мипами, значения — в sRGB. Поля объекта `texture`,
  `uv_scale`, `world_uv`, `roughness`, `metallic`, `emissive`; материалы кэшируются
  по спеке (одинаковые объекты батчатся). Мировые (box) UV дают равномерную
  плотность текселей на стенах и полах при любом масштабе куба; материал по
  умолчанию — диэлектрик (metallic 0, roughness 0.85). Редактор: панель «Материал
  поверхности» (текстура, uv scale, мировые UV, roughness/metallic/emissive).
- **Постобработка (G3)**: сцена рисуется в offscreen HDR-таргет (`Rgba16Float`),
  в поверхность пишет пост-пасс: bloom (bright-pass и разделимое размытие в
  ¼ разрешения — светятся лампы, артефакты и проявленные аномалии, цвет которых
  поднят выше единицы), виньетка и ACES + sRGB (шейдеры сцены отдают линейный
  HDR). Настройки в рендере (`PostSettings`: виньетка 0.35, порог bloom 0.9,
  интенсивность 0.45); клиент переключает их клавишами F6 (виньетка), F7
  (intensity: 0/0.25/0.45/0.8), F8 (порог: 0.6/0.9/1.2) — текущие значения
  на пару секунд показывает подсказка в углу экрана.
- Smoke: `cargo run -p zn-client -- --level {demo_zone,base,svalka,podzemka}` —
  текстуры поверхностей, тени от солнца, виньетка; лампы Подземки светятся
  (emissive + bloom).

## Тестовые сборки: лаунчер, сервер и сессии (M6)

Автоматический контур тестирования: пуш в `main` → CI собирает клиент и сервер
→ релиз «dev» → тестеры получают обновления через лаунчер, бокс `192.168.0.47`
тянет сервер сам. Репозиторий приватный, хостинг бесплатный (квота Releases).

### Карта хранения

| Что | Где | Кто пишет |
|---|---|---|
| Исходники, контент, история | git-репо `Otakyooo/ai_games` (диск `E:\ai_games`) | dev |
| Сборки: `zona-dev-win-x64.zip` + `zona-launcher-x64.zip` + `zona-server-linux-x64.tar.gz` + `manifest.json` | GitHub Releases, rolling prerelease «dev» (2 zip + 2 лаунчер-зипа + 2 tar + 1 manifest) | CI (`release.yml`) |
| Игровой сервер | `192.168.0.47`: `/opt/zona/zn-server`, данные `/opt/zona/data/` | скрипт обновления на боксе |
| Стэши профилей игроков | `192.168.0.47:/opt/zona/data/stashes.ron` (`--stash-file`; переживают редеплой и рестарт) | сервер |
| Лаунчер | куда распакует тестер bootstrap-zip (рекомендуем `%LOCALAPPDATA%\ZONA\launcher`) | тестер (1 раз) |
| Конфиг лаунчера (канал, **выбранная игроком папка**, «свой сервер») | `%LOCALAPPDATA%\ZONA\launcher-config.json` | лаунчер |
| Игра: `zn-client.exe` + `content/` | **папку выбирает игрок** при первом запуске (дефолт `%LOCALAPPDATA%\ZONA\channels\dev`) | лаунчер |
| Версия установленной сборки | `<папка-игры>\..\installed.json` (tmp+rename) | лаунчер |
| Временные файлы обновления | `<папка-игры>\..\staging-<pid>\` (удаляются), бэкап `game.old\` — до успешного свапа | лаунчер |
| Файлы самообновления лаунчера | `<exe>.old` (до следующего старта) / `<exe>.new` (ручная замена) рядом с запущенным | лаунчер |
| Версия сборки на боксе | `/opt/zona/installed` (простой текст) | `deploy/zona-update.sh` |

### CI и релизы (`.github/workflows/release.yml`)

- Пуш в `main` (или `workflow_dispatch` с `build_override` для hotfix-пересборки:
  `run_number` при re-run не меняется) → job `client` (windows-latest) + job
  `server` (ubuntu-latest; нативная Linux-сборка заодно верифицирует
  кросс-платформенность) → publish: rolling prerelease «dev» + `manifest.json`.
  Deploy-job'а нет — обновление на боксе pull-моделью (CI в LAN не заходит).
- Предусловия (делает dev один раз): secret `ZONA_RELEASE_TOKEN` — fine-grained
  PAT `Contents: read` на этот репо (вкомпилируется в лаунчер через
  `option_env!`, иначе приватные ассеты не скачать); repo variable
  `ZONA_SERVER_ADDR` — адрес туннеля (уходит в `manifest.server_addr`).
- Прунинг в релизе: 2 свежих zip + 2 tar + 1 manifest; `strip = true` в
  release-профиле — иначе квота Releases кончится.

### Лаунчер и обновления

- `manifest.json` в релизе «dev»: `version` (`0.1.<run_number>`),
  `url`/`sha256`/`size` клиентского zip, `server` (tar для бокса), `server_addr`
  (куда коннектиться), `build`/`commit`/`created_at`.
- Обновление: скачивание (3 попытки, бэкофф, прогресс) → SHA-256 → распаковка
  (zip-slip guard) → атомарный свап `game` → `game.old` → новая (сбой → откат)
  → `installed.json`. Если клиент запущен — «закройте ZONA» (exe захвачен с
  share=0), установка не трогается.
- Папку установки выбирает игрок: первый запуск — диалог (GUI) или вопрос
  (CLI, `Enter` = дефолт); флаг `--install-dir <путь>`; «Папка…» в GUI
  переносит с подтверждением удаления старой.
- GUI (режим по умолчанию): «Играть» (ensure update → запуск), «Обновить»,
  «Папка…», «Свой сервер» (`host:port`, приоритетнее манифеста — для отладки),
  прогресс и статусы. `--cli` — консольный режим: `--channel`, `--check`
  (только проверить), `--console`, `--version`. Флаги `--install-dir`/`--channel`
  работают и в GUI-режиме (засеивают конфиг).
- `ZN_PROFILE`: не задан — лаунчер подставляет `%USERNAME%`, стэши не теряются.
- dev-режим: `ZN_LAUNCHER_DEV=1` или `Cargo.toml` рабочего дерева рядом с exe —
  лаунчер запускает `target/<profile>/zn-client.exe` без скачиваний.
- SmartScreen: у тестеров будет предупреждение на неподписанный exe —
  «Подробнее» → «Выполнить»; код-подпись — когда появится бюджет.
- **Обновление самого лаунчера (M6-8)**: манифест несёт отдельный блок
  `launcher { version, url, sha256, size }` со своим ассетом
  `zona-launcher-x64.zip`. Лаунчер сверяет СВОЮ версию (штамп CI
  `ZONA_LAUNCHER_VERSION` = версия релиза, либо `<exe>.lversion` после
  последней подмены) с `launcher.version` и при отставании качает зип,
  проверяет sha256, подменяет себя и перезапускается — **без привязки к
  обновлению игры**. Откатов нет: и бандл из zip, и ассет манифеста
  применяются только если их версия строго новее запущенного лаунчера.
  Не скачалось — предупреждение, «Играть» доступна, повтор на старте.
- **Удалённый хотфикс лаунчера** (без CI и без перекачки игры):
  `scripts/publish-launcher-update.ps1 -LauncherVersion 0.1.901 -Build`
  (или `-LauncherZip <путь>`) — собирает лаунчер, грузит зип в релиз «dev»
  и правит ТОЛЬКО блок `launcher{}` в манифесте. Игроки подхватывают при
  следующем старте лаунчера. Нужен GH_TOKEN с правами на Releases.
- **Самообновление лаунчера** (M6-7, бандл): клиентский zip несёт и свежий
  `zn-launcher.exe`. После обновления игры лаунчер сравнивает версии; при
  отличии — rename запущенного образа в `.old` (Windows это разрешает),
  копирование свежего на исходный путь, relaunch. `.old` удаляется на
  следующем старте. Несмогли заменить (образ занят/каталог read-only) —
  рядом кладётся `.new`, пользователь меняет вручную.
- Bootstrap-нюанс: лаунчеры версий <=0.1.4 блока `launcher{}` не знают и
  обновляются бандлом из клиентского zip (как раньше); первый лаунчер с
  механикой M6-8 долетает как часть клиентского zip.
- **Сеть и прокси**: лаунчер читает прокси из окружения
  (`HTTPS_PROXY`/`ALL_PROXY`/`HTTP_PROXY` + `NO_PROXY`; на Windows также
  системный прокси из реестра). Нужно там, где прямой Rust-TLS ломается
  фильтрами (DPI/антивирус): симптом — « failed to parse header value».
  Транспортные сбои ретраятся 3 раза с бэкоффом; при непарсящемся ответе
  лаунчер подсказывает про антивирус/прокси и `https_proxy`.
- PAT в бинарнике теоретически извлекаем: он read-only и только на этот репо,
  тестеры доверенные. Ротация: перегенерить PAT → обновить secret
  `ZONA_RELEASE_TOKEN` (и `/etc/zona/update.env` на боксе) → пуш в main
  (лаунчер пересобирается).

### Сервер (192.168.0.47)

- `/opt/zona/zn-server --bind 127.0.0.1 --port 7700 --content-root /opt/zona/content
  --stash-file /opt/zona/data/stashes.ron` под systemd
  (`deploy/zona-server.service`, `Restart=always`). **Второй жилец рядом с
  anicast: ограничений ресурсов намеренно нет** — cgroup-лимиты добавим, только
  если ZONA реально начнёт мешать; anicast-сервисы, каталоги и MCP не трогаем.
- Обновление — pull-моделью (`deploy/zona-update.sh`, таймер раз в 5 минут):
  `manifest.json` → сверка версии с `/opt/zona/installed` → tar.gz → SHA-256 →
  подмена с `.bak` → рестарт → health-check (порт слушается; промах → откат
  бинарника и контента). Логи — `journalctl -u zona-update -n 50`.
- Вход для игроков — **playit.gg** (бокс за NAT): агент на боксе, туннель
  `7700/udp → 127.0.0.1:7700`, публичный адрес `xxx.playit.gg:7700` уходит в
  `manifest.server_addr` — тестер жмёт «Играть» и коннектится сразу, **ноль
  сторонних программ**. Смена адреса — `scripts/update-server-addr.ps1
  -ServerAddr xxx.playit.gg:7700` с машины dev'а (пустой адрес = offline для
  всех). Фолбэки: проброс UDP 7700 на роутере; WireGuard до финского VPS —
  только крайний вариант, он слабый.
- Bootstrap (один раз): SSH на `.47` (`admin_lama`, ключ `id_ed25519` уже
  авторизован) → `/opt/zona`, `/etc/zona/update.env`
  (`ZONA_PAT`, root-only) → `cp deploy/zona-*.service deploy/zona-update.timer
  /etc/systemd/system/` → `systemctl enable --now zona-server
  zona-update.timer` → агент playit (`deploy/playit.env`) → адрес туннеля в
  `ZONA_SERVER_ADDR`.

### Тестовые сессии

- Один раз: тестер получает bootstrap-zip с `zn-launcher.exe`, распаковывает
  куда угодно, запускает, выбирает папку — дальше всё автоматически.
- «Играть» = ensure-update → запуск с `--server` из манифеста (или поля «Свой
  сервер» для отладки конкретного адреса).
- Пустой или битый `server_addr` → оффлайн с предупреждением (игра стартует в
  одиночном уровне).
- Локальная отладка без релиза: `ZN_LAUNCHER_DEV=1` + `cargo run -p zn-launcher`
  из рабочего дерева.

## Дорожная карта

- **M0**: каркас workspace + CI (готово)
- **M1**: вертикальный срез движка (окно, FPS-камера, character controller,
  рендер инстансированной сцены) — готово, валидация: тесты/clippy/fmt зелёные
- **M2**: контент-пайплайн (glTF/KTX2-импорт, CPU-типы + GPU-кэши), редактор
  уровней, стриминг с LRU-кэшами — готово, валидация: тесты/clippy/fmt зелёные,
  клиент запускается из `game/content`
- **M2.5**: бэклог M2 — wgpu 30, BasisU-транскод, CPU-мипы, Blend-конвейер,
  кулинг инстансов, мультиматериал, редактор на egui-wgpu — готово, валидация:
  тесты/clippy/fmt зелёные, smoke клиента и редактора
- **M3**: netcode (клиентский prediction/reconciliation, интерполяция удалённых
  игроков), dedicated-сервер (1 матч, ≤ 10 игроков), UDP-протокол v2 — готово,
  валидация: тесты/clippy/fmt зелёные, smoke: сервер + 2 клиента
- **M4**: геймплей Зоны — подсрезы **M4a** (бой: hitscan, зоны урона,
  смерть/респавн, HUD, события выстрелов), **M4b** (лут: ящики и трупы,
  инвентарь 8×5 с весом, выброс/подбор, лечение) и **M4c** (аномалии: жгучая и
  гравитационная, болты-щупы, артефакты) готовы, **M4d-1** (мир локаций: База,
  Кордон, Свалка, Подземка, переходы, пузыри, склад базы), **M4d-2**
  (экстракция: круги с процентом сейва, персист стэшей профилей в `stashes.ron`),
  **M4d-3a** (выживание данными: расход патронов, лечение едой, эффекты
  артефактов из инвентаря) и **M4d-3b** (нокдаун вместо мгновенной смерти,
  выбросы с предупреждением и уроном вне базы) готовы — валидация:
  тесты/clippy/fmt зелёные, smoke: сервер + 2 клиента; далее M4e —
  прокачка/квесты/дневник
- **M4g**: графика — **G1** (атмосфера: солнце/туман/градиентное небо; тени PCF),
  **G2** (материалы: встроенные процедурные текстуры, тайлинг, мировые UV,
  emissive), **G3** (постобработка: HDR-таргет, bloom, виньетка, настройки
  клавишами F6–F8) и **G4a** (undo/redo правок в редакторе) готовы, валидация:
  тесты/clippy/fmt зелёные; далее продолжение G4 (апгрейд редактора) и G5 дизайн
  локаций
- **A1**: аудио — `zn-audio` на kira подключён к клиенту, процедурные звуки
  (выстрел, попадание, подбор, болт, лечение, смерть, панель, переход),
  F9/F10 — готово, валидация: тесты/clippy/fmt зелёные; слышимость — ручной
  smoke (сервер + 2 клиента)
- **M5**: аккаунты, БД, база между рейдами
- **M6**: лаунчер (GUI + CLI, выбор папки установки, канал dev, манифестные
  обновления с SHA-256 и атомарным свапом, самообновление лаунчера),
  авто-dev-сборки в GitHub Releases (`release.yml`) и сервер тестовых
  сессий на `192.168.0.47` (pull-обновление с откатом, playit-вход) —
  готово, валидация: тесты/clippy/fmt зелёные; инсталлятор — позже

## Звук (A1)

- **Процедурные звуки**: короткие моно-WAV синтезируются в памяти
  (детерминированно, без бинарных ассетов): выстрел, попадание, подбор, бросок
  болта, срабатывание болта в аномалии, лечение, смерть, панель интерфейса,
  переход между локациями; гудок экстракции заведён под M4d-2.
- **Движок**: `zn-audio` на kira подключён к клиенту (раньше звука не было
  вовсе). Без устройства звука — молчаливый режим, игра не падает (CI).
- **Управление**: F9 — цикл громкости (0/25/50/75/100%), F10 — мьют; текущие
  значения — в подсказке в углу экрана.
- **Источники**: события снапшотов (чужие выстрелы, смерти, проявления аномалий)
  и локальные действия (огонь, лечение, бросок, подбор, панели, переход).
  Сервер и протокол не менялись.

## Управление (M1–M4d)

WASD — движение, мышь — обзор, ЛКМ — огонь (удержание), Space — прыжок,
Esc — отпустить курсор (клик по окну возвращает захват).
E — обыск/подбор/закрыть, G — бросить болт, I — инвентарь, H — склад (на базе,
M4d), Enter — взять выбранное (обыск/склад) / использовать (инвентарь) / сдать
ячейку в склад (инвентарь при открытом складе), T — взять всё, Q — выбросить
выделенный стак, ↑/↓ — перемещение выбора в панели, ←/→ — фокус между панелями
обыска, склада и инвентаря (когда панель одна — перемещение по сетке инвентаря),
F6 — виньетка вкл/выкл, F7 — интенсивность bloom, F8 — порог bloom (M4g-G3),
F9 — громкость звука, F10 — мьют (A1).
В сетевой сессии заголовок окна показывает локацию мира (M4d) и статус:
`подключение…` / `ping N ms` / `нет связи` (после перехода в offline).
