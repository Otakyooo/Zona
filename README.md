# ZONA

Собственный игровой движок (Rust), игра и лаунчер. Сеттинг — Зона в духе братьев
Стругацких («Пикник на обочине»): аномалии, артефакты, экспедиции, исследования.

## Что это

- **Движок с нуля**: `winit` + `wgpu` (Vulkan/DX12) + `rapier3d` + собственный ECS-слой
  на `hecs` с фиксированным тиком симуляции.
- **Игра**: 3D FPS, extraction-рейды (заход со своим снаряжением, добыча выносится,
  смерть = потеря лута), между рейдами — база. PvP + PvE, лут, выживание, прокачка,
  квесты, отрядные сессии 5–10 игроков.
- **Лаунчер**: свой Rust-лаунчер, обновления по `manifest.json` с GitHub Releases
  (zstd-архивы + SHA-256).

## Сборка и запуск (Windows)

```powershell
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p zn-client                            # offline: demo_zone
cargo run -p zn-client -- --level kordon          # offline: одиночная сцена
cargo run -p zn-client -- --server 127.0.0.1:7700 # мир локаций (M4d)
cargo run -p zn-server -- --port 7700 --max-players 10   # мир локаций
cargo run -p zn-server -- --level demo_zone               # одиночная сцена
cargo run -p zn-server -- --sim-latency-ms 120 --sim-loss-pct 10
cargo run -p zn-launcher -- --channel dev
cargo run -p zn-tools-editor --bin zn-editor
```

Платформа релиза: Windows x64 (wgpu выбирает Vulkan/DX12 автоматически).

## Тулчейн

- Минимальная версия Rust — **1.95** (`rust-version` workspace).
- Целевой тулчейн для разработки: `stable-x86_64-pc-windows-msvc`
  (`rustup default stable-x86_64-pc-windows-msvc`), как в CI. Запуск клиента —

  ```powershell
  cargo run -p zn-client
  ```

  Требуется MSVC-линкер из **Visual Studio Build Tools** (workload
  «Разработка классических приложений на C++» + Windows SDK):

  ```powershell
  winget install --id Microsoft.VisualStudio.2022.BuildTools `
    --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.Windows11SDK.22621 --includeRecommended"
  ```
- Альтернатива — `stable-x86_64-pc-windows-gnu` (rustup):
  `.cargo/config.toml` проекта принудительно переназначает gnu-линкер на
  bundled-gcc тулчейна rustup (`lib/rustlib/x86_64-pc-windows-gnu/bin/self-contained/...`),
  потому что системный WinLibs (Brecht Sanders) gcc, прописанный глобально в
  `~/.cargo/config.toml` этой машины, линкует бинарники с битой таблицей импортов.
  Ранее из-за этого `zn-client` падал на старте с `0xC0000005` в
  `std::sys::pal::windows::init`; ныне разработка идёт на MSVC, где проблемы нет.
- CI (`.github/workflows/ci.yml`) использует стандартный MSVC-тулчейн GitHub-runner.

## Контент

Уровни — RON-файлы `game/content/levels/<имя>.scene.ron`, ассеты —
`game/content/assets/` (glTF/GLB, PNG/JPEG, KTX2: uncompressed и Basis Universal).
Клиент читает
корень контента из `--content-root` (или `ZN_CONTENT_ROOT`, по умолчанию
`game/content`) и уровень из `--level <имя>`; если файл не найден — предупреждение
и fallback на `demo_zone()`. Редактор: `cargo run -p zn-tools-editor --bin zn-editor` —
New/Open/Save `.scene.ron`, орбитальная камера, пикинг объектов, gizmo
(перемещение/вращение), браузер ассетов с размещением (клик пересекает луч с
землёй y=0 или ближайшим боксом коллайдера), панель свойств (position, scale,
yaw, tint, asset, material, collider, solid). Одноразовая выгрузка демо-уровня:

```powershell
cargo run -p zn-tools-editor --bin zn-editor -- --emit-demo game/content/levels/demo_zone.scene.ron
```

Выгрузка всего мира M4d (реестр + сцены локаций, M4d-1):

```powershell
cargo run -p zn-tools-editor --bin zn-editor -- --emit-world game/content
```

Мир локаций: реестр `game/content/locations.ron` (`id`, `name`, `scene`, `base` —
признак безопасной базы) и сцены `game/content/levels/{base,kordon,svalka,podzemka}.scene.ron`.
Мир встроен и в код (`zn-scene`: `LocationRegistry::builtin`/`Scene::builtin_world`) —
сервер и клиент падают на него, если файлы не прочитаны (хэши обязаны сойтись).
Схема объекта: `position`, `scale`, `yaw`, `color`, `asset` (`builtin://cube/sphere/
cylinder/quad` или относительный путь к glTF), `material` (имя материала внутри
ассета), `collider` (`box`/`cylinder`/`sphere`, по умолчанию box у solid-объектов),
`solid`, `loot` (ящик: список `[(item, count), …]`). Сцена дополнительно несёт
`spawn`/`spawn_yaw`, `anomalies`, `transitions` (пешие переходы: `position`,
`radius`, `target`, `target_position`, `target_yaw`, `label`), `bubbles`
(кандидаты пузырей: якорь + радиус) и `bubble_arrivals` (точки прибытия
телепорта). Неизвестные поля получают
значения по умолчанию (back-compat с RON M1).
Каталог предметов — `game/content/items/items.ron` (`key`, `display_name`,
`weight_kg`, `stack_max`, `use_effect` с лечением); сетевой номер предмета —
индекс в каталоге, отсортированном по `key`, и хэш каталога едет в handshake.
Asset-ключи — строки, межкратные ID (`MeshId`/`MaterialId`) живут только внутри
`zn-render`. Загрузка ассетов в клиенте — фоновый поток (std::thread + mpsc);
не загруженное показывается builtin-кубом. GPU-кэши с LRU-выселением по бюджетам
256 МиБ (меши) / 512 МиБ (текстуры). Текстуры грузятся с CPU box-мип-цепочкой
(сэмплер LinearMipLinear). Материалы с `AlphaMode::Blend` рисуются вторым
проходом back-to-front после непрозрачных.

KTX2: uncompressed и Basis Universal (ETC1S/BasisLZ и UASTC, в т.ч. с
Zstd-суперкомпрессией) — транскод в RGBA8 на CPU через `basisu`; BCn-compressed
форматы вне объёма (фолбэк на PNG/JPEG/uncompressed KTX2). Прокси-коллайдеры
статики строятся при (пере)загрузке уровня; смена масштаба объекта в рантайме
их не пересчитывает.

## Сеть (M3–M4d)

Dedicated-сервер и клиент общаются по UDP (bincode, протокол v6; одна датаграмма —
одно сообщение; бюджет 1400 Б, фрагментация не реализована). Один процесс
сервера — один матч, до 10 игроков. С M4d сервер без `--level` ведёт мир
локаций (одна симуляция на локацию), с `--level <имя>` — одиночную сцену.

- **Клиент**: `--server host:port`. Handshake `ClientHello` (версия протокола +
  `content_hash` уровня + `items_hash` каталога + имя) с повтором каждые 500 мс;
  `ServerReject` (версия/контент/нет слотов) → offline. Дальше — `InputPacket`
  (последние 4 инпута: потеря датаграммы не превращается в потерю движения),
  `Ping` раз в секунду (RTT — в заголовке окна), `ClientBye` при выходе.
- **Симуляция** 60 Гц — общая кинематика `zn-sim` у клиента и сервера; снапшоты
  30 Гц с персональным `acked_input_tick`. Клиент предсказывает движение локально
  и сверяет со снапшотом: reconcile = восстановление состояния → реплей
  неучтённых инпутов → сравнение; небольшие поправки гаснут визуально (~0.15 с),
  большие (> 2 м) — мгновенный снап.
- **Удалённые игроки** рисуются капсулами с интерполяцией (рендер на 100 мс
  назад, пара снапшотов вокруг тика, yaw по кратчайшей дуге); цвет детерминирован
  по `player_id`. Себя клиент не рисует.
- **Таймауты**: сервер забывает клиента после 5 с тишины; клиент уходит в offline
  после 3 с без снапшотов (заголовок окна: «нет связи»). Реконнекта нет — перезапуск.
- **Ограничения M3**: нет фрагментации (≤ 1400 Б), игроки не сталкиваются друг с
  другом, сервер авторитетен (античит вне рамок); бой — в M4a, лут и инвентарь —
  в M4b, аномалии и болты — в M4c ниже.
- **Консоль сервера**: `status`, `list` (с локацией клиентов), `kick <id>`,
  `spawn` (отладочный игрок), `loot <id> <item> <count>`, `tp <id> <location>`,
  `bubbles [<location>]`, `quit`. Флаги `--sim-latency-ms`/`--sim-loss-pct`
  имитируют задержку и потери исходящих (для ручной проверки, не для CI).
- **Smoke**: `cargo run -p zn-server` + два `cargo run -p zn-client -- --server
  127.0.0.1:7700`; выход одного клиента убирает его капсулу у второго, kick с
  консоли — то же самое.

## Бой (M4a)

PvP-бой: серверный hitscan-винтовкой (авто-огонь), урон зонами по высоте попадания,
смерть с респавном, HUD и события выстрелов для всех клиентов.

- **Стрельба**: ЛКМ (при захваченном курсоре) удерживается — выстрел каждые
  8 тиков (~7.5/с), дальность 100 м. Луч выходит из глаз (1.62 м), стены уровня
  блокируют выстрел, хитбокс игрока — капсула; отдача и разброс не реализованы.
- **Урон**: 100 HP; торс — 25, голова ×2 (50), ноги ×0.6 (15). Зоны по высоте от
  ступней: голова ≥ 1.5 м, торс 0.8–1.5 м, ноги < 0.8 м.
- **Смерть/респавн**: 0 HP — смерть: мёртвый не двигается и не стреляет, но может
  осматриваться, у других не рисуется — вместо капсулы остаётся труп-контейнер
  (M4b); через 180 тиков (3 с) — респавн на точке спавна уровня с полным
  здоровьем. Friendly fire всегда включён.
- **Протокол**: `health` в состоянии игрока, `GameEvent` (`Shot` — трейсер и
  вспышка у всех, `Death` — с именами от сессии); события копятся между
  снапшотами и едут в них (30 Гц), размер датаграммы проверен тестом
  (10 игроков + события; с M4c бюджет — 1400 Б под болты и аномалии).
- **HUD** (egui, пассивный — ввод не перехватывает): прицел, HP-полоска и число,
  kill-фид (3 последние смерти, 4 с, «Вы» для себя), экран смерти с именем убийцы
  и отсчётом до возрождения.
- **Ограничения M4a**: без лаг-компенсации (хитрег по позиции на момент обработки
  тика), без отдачи/разброса/звука, без PvE, одно оружие (винтовка), урона от
  падения нет, анимаций смерти нет (труп — лежачий бокс, M4b).
- **Smoke боя**: сервер + 2 клиента; стрельба ЛКМ, HUD и килл-фид, смерть — экран
  «ВЫ УБИТЫ» и респавн через ~3 с.

## Лут и инвентарь (M4b)

Обыск контейнеров, инвентарь с весом, выброс/подбор предметов и лечение аптечкой
или бинтом. Игра не встаёт на паузу: панели passive, курсор остаётся в игре.

- **Каталог предметов**: `game/content/items/items.ron` — 8 предметов (патроны,
  бинт, болт, консервы, аптечка, водка; артефакты «Жар-камень» и «Тягун»
  добавлены в M4c): вес, максимум стопки, эффект. Сетевой номер предмета —
  индекс в каталоге, отсортированном по `key`; хэш каталога едет в handshake
  (несовпадение — отказ как при другом уровне).
- **Ящики**: объекты сцены с полем `loot` (`[(item, count), …]`, позиция — центр
  крышки); обыск — E: цель в радиусе 2 м (XZ) и в конусе взгляда, выбор — по
  прицелу, как у боя. Панель обыска персональная: чужой лут не виден, содержимое
  общее и убывает для всех.
- **Инвентарь**: сетка 8×5, лимит 50 кг; автоукладка — сначала в существующий
  стак, затем в первую свободную ячейку. Взять: Enter (выделенную строку) или
  T (всё, что влезает по весу); выбросить: Q (выделенный стак улетает перед
  игроком); использовать: Enter на ячейке инвентаря.
- **Лечение**: аптечка +50 HP за 2 с, бинт +25 HP за 1 с; расход — в конце,
  смерть отменяет без расхода. Не начинается при полном HP и во время активного
  лечения. Прогресс — зелёная полоска над HP.
- **Трупы**: смерть оставляет на месте игрока лежачий бокс-контейнер с его лутом
  (убийца забирает добычу); труп гаснет через 5 минут. Обыск — как у ящиков;
  панель закрывается при отходе (> 3 м), смерти или исчезновении трупа.
- **Протокол v4** (в M4c обновлён до v5, в M4d — до v6): `ClientHello` + `items_hash`; `Interact`/`InventoryAction`
  (монотонный `tick` — действия уходят с 4-кратным повтором, сервер
  дедуплицирует), персональные `InventoryUpdate`/`ContainerUpdate` (контейнер
  `0` — закрыт), `loot`/`corpses` в снапшотах (позиции — квант 0.1 м, yaw —
  1/256 оборота).
- **HUD**: панели обыска и инвентаря (справа снизу, фокус — ярче рамкой),
  название и вес выбранного, «Вес: X / 50 кг», строка подсказки «[E]
  Обыскать/Подобрать» под прицелом.
- **Ограничения M4b**: нет торговли и передачи предметов между игроками (только
  трупы/земля), еда и водка не используются (заготовка под M4d), патроны не
  расходуются, drag&drop нет (автораскладка), на земле ≤ 32 предмета (старейшие
  вытесняются), звук отложен, лут трупа чужому не виден (только сам труп).
- **Smoke лута**: сервер + 2 клиента; ящик у спавна — E, T — взять всё, I —
  инвентарь (вес/выбор), Q — выброс виден второму игроку, аптечка — полоска
  лечения, смерть — труп с лутом.

## Аномалии и артефакты (M4c)

Две аномалии в demo_zone, болты как «щуп» и артефакты, лежащие в аномалиях с
начала рейда. Аномалии не входят в столкновения: эффекты считает симуляция,
визуал — клиент.

- **Аномалии**: жгучая — урон внутри сферы (радиус 3 м): каждые 15 тиков 2–6 HP
  по близости к центру; гравитационная — тянет к оси (радиус 3.5 м): у центра
  5 м/с — сильнее пешего шага (5.5), но спринт (8.5) выносит, урона нет. Центр
  сферы — якорь + радиус вверх, «сердце» цели — ступни + 0.9 м. Смерть в
  аномалии — обычный труп с лутом, в килл-фиде подписана «Аномалия» (убийцы нет).
- **Болт**: G — бросок (1 болт из инвентаря, кулдаун 20 тиков, в полёте ≤ 12
  болтов на мир, живёт до 10 с). Летит по дуге (та же гравитация, скорость
  18 м/с), останавливается статикой и падает предметом — подбирается E. Игрокам
  урона не наносит. Болт, влетевший в аномалию, гибнет со вспышкой: аномалия
  ярко проявляется на 5 с — видят все (событие в снапшоте).
- **Артефакты**: «Жар-камень» в жгучей и «Тягун» в гравитационной аномалии
  demo_zone; лежат в якоре с начала матча, подбор — как обычный предмет на земле.
  Эффектов и ценности у них нет (заготовка под M4d).
- **Протокол v5**: `ThrowBolt` (дедупликация по tick), `bolts` в снапшотах
  (id, владелец, квантованная позиция), `AnomalyRevealed` (индекс аномалии и
  точка срабатывания болта — для вспышки). Снапшот самого полного случая
  (10 игроков + 32 предмета + 4 трупа + 12 болтов + события) ≤ 1400 Б — без
  фрагментации UDP на Ethernet.
- **Визуал**: аномалии — еле заметные мерцающие сферы (альфа ~0.12), по цвету
  типа (жар — оранжевый, тяга — фиолетовый); проявленные — ярче, плюс вспышка в
  точке срабатывания. Болты интерполируются между снапшотами.
- **Ограничения M4c**: без телепорт-эффектов, радиации/дозиметра, выбросов,
  порчи лута в аномалиях и звука; аномалии влияют только на игроков и болты.
- **Smoke аномалий**: сервер + 2 клиента; прогулка в жгучую — HP падает, смерть
  с подписью «Аномалия» и трупом; бросок G в гравитационную — вспышка и
  подсветка; артефакт — E у якоря аномалии.

## Мир локаций и база (M4d-1)

Четыре локации, связанные пешими переходами и пузырями-телепортами; на базе —
спавн и персональный склад, куда автоматически уходит вся добыча.

- **Локации**: База (id 0), Кордон (1 — переработанный demo_zone с ящиками,
  аномалиями и артефактами), Свалка (2), Подземка (3). Каждая локация — своя
  симуляция на сервере; игрок живёт в одной из них, снапшоты и удалённые игроки
  видны только внутри своей локации. Расстояние до базы — 0/1/2/2.
- **Хэш мира**: handshake покрывает реестр и все сцены (`world_content_hash`);
  клиент без `--level` в сети грузит `locations.ron` и сцены сам, расхождение —
  отказ, как при другом уровне. В одиночном режиме (`--level`) хэш — только
  сцены, переходы и пузыри выключены.
- **Переходы пешком**: круг `radius` на полу вокруг `position` — вход переключает
  в `target` (точка `target_position` с поворотом `target_yaw`) без таймера;
  гистерезис не даёт дребезжать у границы. У ворот базы точки прибытия отнесены
  так, чтобы обратный переход не срабатывал сразу.
- **Пузыри**: в сцене — кандидаты (`bubbles`) и точки прибытия (`bubble_arrivals`);
  сервер держит 2–3 активных на карту. Вход — телепорт (проверяется «сердце»
  игрока: ступни + 0.9 м): локация строго ближе к базе (со Свалки/Подземки — на
  Кордон, с Кордона — на Базу); ближе некуда — игрок прибывает в точку
  `bubble_arrivals` своей же сцены. Использованный пузырь исчезает и через 90 с
  рождается в случайном свободном кандидате. Активные якоря едут в снапшотах
  локации — клиент рисует полупрозрачные сферы (радиус — от кандидата сцены).
- **База и склад**: вход на базу (пешком или пузырём) автоматически сдаёт весь
  инвентарь в персональный склад (пока 100 %; проценты сейва по методам выхода
  утвердим в подшаге про экстракцию). Склад хранится до отключения игрока:
  реконнект = новый `player_id` и пустой склад. Операции — только на базе,
  панель H: Enter на складе берёт стопку, при фокусе на инвентаре Enter сдаёт
  ячейку; стопки не сливаются. Сервер шлёт свежий `StashUpdate` при входе на
  базу и после Welcome.
- **Протокол v6**: `ServerWelcome.location`; `StashAction` (`Put { slot }` /
  `Take { index }`, дедупликация по tick, повтор как у прочих действий) и
  персональный `StashUpdate`; `LocationChanged { location, position, yaw }` —
  клиент пересоздаёт сцену, коллайдеры и локальную симуляцию, переносит игрока
  в точку прибытия и кратко вспыхивает белым экраном; `bubbles` в снапшотах.
- **HUD/титул**: заголовок окна — `ZONA — База · ping N ms` (локация + статус
  связи); панель склада рисуется слева от обыска/инвентаря, строки контейнера и
  склада совпадают индексами с серверными (неизвестный каталогу предмет —
  строкой-заглушкой, взять его всё равно можно).
- **Ограничения M4d-1**: новые локации — песочницы без PvE-врагов и своего лута
  (кроме Кордона); сигнал (аварийный ТП почти к базе), проценты сейва, выбросы и
  радиация — следующие подшаги; клан/общий склад отсутствует.
- **Smoke мира**: `cargo run -p zn-server` + два `cargo run -p zn-client --
  --server 127.0.0.1:7700`; пройти в ворота (титул меняет локацию, вспышка),
  вернуться на базу с лутом — инвентарь уходит в склад (H, Enter — взять
  обратно; фокус инвентаря + Enter — сдать ячейку); `tp <id> 2` + `bubbles 2`
  на консоли сервера — пузырь на Свалке уносит на Кордон.

## Дорожная карта

- **M0**: каркас workspace + CI (готово)
- **M1**: вертикальный срез движка (окно, FPS-камера, character controller,
  рендер инстансированной сцены) — готово, валидация: тесты/clippy/fmt зелёные
- **M2**: контент-пайплайн (glTF/KTX2-импорт, CPU-типы + GPU-кэши), редактор
  уровней, стриминг с LRU-кэшами — готово, валидация: тесты/clippy/fmt зелёные,
  клиент запускается из `game/content`
- **M2.5**: бэклог M2 — wgpu 30, BasisU-транскод, CPU-мипы, Blend-конвейер,
  кулинг инстансов, мультиматериал, редактор на egui-wgpu — готово, валидация:
  тесты/clippy/fmt зелёные, smoke клиента и редактора
- **M3**: netcode (клиентский prediction/reconciliation, интерполяция удалённых
  игроков), dedicated-сервер (1 матч, ≤ 10 игроков), UDP-протокол v2 — готово,
  валидация: тесты/clippy/fmt зелёные, smoke: сервер + 2 клиента
- **M4**: геймплей Зоны — подсрезы **M4a** (бой: hitscan, зоны урона,
  смерть/респавн, HUD, события выстрелов), **M4b** (лут: ящики и трупы,
  инвентарь 8×5 с весом, выброс/подбор, лечение) и **M4c** (аномалии: жгучая и
  гравитационная, болты-щупы, артефакты) готовы, **M4d-1** (мир локаций: База,
  Кордон, Свалка, Подземка, переходы, пузыри, склад базы) готов — валидация:
  тесты/clippy/fmt зелёные, smoke: сервер + 2 клиента; далее M4d — выживание,
  нокдаун/смерть, глобальные события, экстракция и сейв лута, затем M4e
  прокачка/квесты/дневник
- **M5**: аккаунты, БД, база между рейдами
- **M6**: лаунчер, обновления, инсталлятор

## Управление (M1–M4d)

WASD — движение, мышь — обзор, ЛКМ — огонь (удержание), Space — прыжок,
Esc — отпустить курсор (клик по окну возвращает захват).
E — обыск/подбор/закрыть, G — бросить болт, I — инвентарь, H — склад (на базе,
M4d), Enter — взять выбранное (обыск/склад) / использовать (инвентарь) / сдать
ячейку в склад (инвентарь при открытом складе), T — взять всё, Q — выбросить
выделенный стак, ↑/↓ — перемещение выбора в панели, ←/→ — фокус между панелями
обыска, склада и инвентаря (когда панель одна — перемещение по сетке инвентаря).
В сетевой сессии заголовок окна показывает локацию мира (M4d) и статус:
`подключение…` / `ping N ms` / `нет связи` (после перехода в offline).
